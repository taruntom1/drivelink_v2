# libdrivelink rules

- `libdrivelink` is C++23 without Qt/ROS/firmware dependencies. Public namespace is `drivelink`; protocol code is `drivelink::protocol`. Asio is private. Dependencies stay version/SHA256-pinned; never edit vendored source.
- Discover module types/values/actions from the device, never a compiled module table. Generated constants are for core/system IDs only. Share framing, Scanner and Reader/Writer; keep descriptor/scalar parsing pure/tested. Validate complete lengths/pages/counts and payload limits; mismatches are explicit.
- One Asio I/O thread owns sockets/serial/TX and periodic time. Sync callers serialize except emergency DISARM; never call sync on I/O. `Client` sync is single-caller; typed async callables own their inputs and run on the serial service executor with a temporary Client. Callbacks are dispatched FIFO, exactly once and in reply order, never inline/on I/O. Bound admission through callback consumption; never drop an accepted completion. DISARM reserves TX space as well as admission and bypasses ordinary service/TX queues.
- Transport failure completes pending work but retains the I/O work guard until explicit close. Serialize close with submission; a checked-but-not-yet-posted request must never land on a stopped context. Close must not depend on peer or application dispatcher progress. Bound event queues and expose drop counters. Release operation-owner locks before cancelling transport request handles: close joins I/O under its closing lock, and I/O completion needs the owner lock.
- DeviceModel retains Session, not a temporary service Client. Publish immutable shared snapshots, tag generations, invalidate readiness on Boot and reload complete metadata. Reload publication preserves current link/runtime/loss state; a delayed result cannot resurrect a disconnected model. Group data is pulled, not dispatched. Seqlock payload words must be atomic C++ objects.
- Managed commands use a bounded producer queue and prefix-only I/O keepalives (a consumer that must feed the watchdog from its own loop, the ROS plugin, turns them off). Consumers supply finite holds; no module-specific semantics. Flush both queued values and pending TX generations before mode changes. Boot, clear and close invalidate traffic; never replay values or arm automatically.
- Correlate type, sequence, family and op. Retry only known-idempotent reads; a mutation timeout has an uncertain outcome. Retire timed-out IDs until reconnect (or an opt-in `retire_quarantine`, for the agent's links that never reconnect); fail explicitly on exhaustion, except DISARM, which may reuse a retired ID. Preserve request family/op and outcome_unknown through service parsing and OTA cleanup; malformed mutation replies are uncertain, local preflight errors are not. Read classification and automatic retry eligibility are separate.
- Time ping IDs, boot/session clock generations and timeout retirement stay separate from core sequence IDs. Stamp on I/O; ClockEstimator stays single-caller, bounded and monotonic. See [time.md](../../docs/protocol/time.md).
- OTA's WRITE retry exception permits only identical offset/data. Batch calls hold ownership, retire missing IDs and respect device window/chunk/payload limits (at most four outstanding). Reconcile uncertain BEGIN/FINISH/CONFIRM through STATUS; never automatically repeat REBOOT. A reboot reply is acceptance only: verify full running ELF identity, slot and core version before CONFIRM, then recheck identity. Cancellation never confirms. See [ota.md](../../docs/protocol/ota.md).
