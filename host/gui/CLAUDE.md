# GUI rules

- GUI remote mode (H3b-1, [gui/README.md](README.md) "Remote mode"): a `LocalConnection` through the agent with its Hello's `client_kind` Gui. It observes first and sets up command groups only while it holds the lease; the agent's Lease events are the truth. Losing the lease forgets the command groups without CMD_CLEAR (the agent cleared them) and cancels an ARM in flight; a grant never arms. Take from another holder needs the operator's explicit safe-to-stop confirmation. Exclusive operations follow the agent's rule (`exclusiveBlocked()`). A live param edit while another client holds the lease is held unsent until the operator applies it (the opt-out lasts one connection). A token is stored only when the user asks.
- GUI ([gui/README.md](README.md)): Qt 6.10 API floor. Figma is the source of the tokens; `tokens.json` and `Theme.qml` are generated by `gen_theme.py`, never hand-edited. Controls take every colour, size and font from `Theme`, only draw and emit requests, and contain nothing module-specific. Keep DISARM reachable: no Qt modal popups (they block the status bar). New icons come from the Figma G2 set, at the bundled Lucide version.
- GUI completions/model notifications run on the GUI thread through a FIFO session dispatcher. Keep its receiver alive through callback drain; stale connection/session generations cannot publish or arm. Bound initial event draining and preserve DISARM requested before link publication or behind an earlier failed DISARM. Observer close waits for an admitted safety request; an unconfirmed forced close must report an uncertain outcome.
- GUI command groups initially send prefixes only. Never infer a semantic hold from descriptor defaults. An already-armed direct connection observes until explicit DISARM acknowledgement, including an armed state seen during discovery followed by watchdog disarm. Never adopt other owners' groups; reconcile uncertain setup and clear only matching owned generation/epoch/refs.
- GUI OTA uses the library workflow (`drivelink/ota.hpp`) and the reboot expectation every reboot uses: REBOOT once, never repeated; CONFIRM only after `classifyOtaBoot` matches the candidate this GUI uploaded, at most once automatically, never after a roll back or cancel. Without a known candidate only the user's explicit Confirm sends CONFIRM. An active update blocks ARM and configuration actions; an unknown or Ready OTA state blocks reboots. The image picker is non-modal and offered only while disarmed; nothing arms while it is open. The only other native dialogs are Tune's session and CSV file dialogs (non-modal, allowed while armed; user decision 2026-11-18) and a custom panel's own file dialogs (the same rules): Esc goes to the dialog while it is open, DISARM stays clickable.
- Custom panels (H2f): module-specific GUI code exists only in `gui/modules/<type name>/`, loaded by the device's type name; its logic is typed C++ with QtTest tests, registered through `registerModulePanels()`. A panel uses the generic backend surface (live rows, actions by key sent once, action results, bounded text files) and adds no backend, wire or safety rule. The IMU calibration panel sends `calibration_apply` only after `calibration_write` replied ok, never re-sends, and records an operation interrupted by unloading as "may have run".
- GUI loop-statistics subscriptions, the Layout live group and Monitor's groups (one per plotted loop) use free slots only, after command setup (live and Monitor after loop statistics, one mutation at a time), record intent before SUB_CONFIG, and are reused or cleared only on an exact owned LIST match; a successful configure drops every other record for that slot; a SUB_CONFIG that lands on a newer boot releases its slot or records it under that boot. The Layout live group exists only while Layout is shown. Monitor refuses an add without a free slot or over 100 % of the link, and caps a group at 1 kHz (the firmware drains each group once per 1 ms).
- Hold rule (user decision 2026-11-17, built in H2d-2): only numeric inputs whose descriptor range is finite and includes 0 are commanded; each loop's inputs split at connect into value groups (hold 0) and keepalive-only groups that never carry values; every value sent is a shown slider value or 0. Manual commands need this window's accepted ARM; DISARM, faults, Boot and close return values to 0 locally. A held slider that loses its press ramps to 0; Latch survives page changes. A live param write to a commanded instance discards its queued values and holds it at 0 until the write ends, then sends a fresh frame (user decisions 2026-11-18).
- For changes to Tune, follow the GUI contracts for [runs](README.md#tune-h2e-1), [sessions and auto re-run](README.md#tune-session-h2e-2) and [plant identification](README.md#plant-identification-h2e-3).
- A requested reboot is never re-sent: the GUI waits for Boot or reopens the link within a bounded window; an unrequested loss waits for the user's Retry. Listing serial ports never opens one (DTR/RTS can reset an ESP).
- GUI Layout sends each SET and layout op once, then `refreshConfigAsync`; an unanswered one is uncertain and read back, never retried. A param field sends on Enter or focus loss only when its text differs from the device value and the text last sent. Esc and DISARM (which takes no focus) cancel an open edit unsent. Layout ops and reboot params are locked while armed; ARM is disabled while a reboot is pending. Rules come from descriptors (loop masks, flags, `ref:` categories, generated source signals), never from type names. The Device settings card (system params) follows the same rules; its limits take effect only through the pending layout, and a safe-mode difference between running and saved values is shown as a note, never as pending ([README](README.md#device-settings)).
- GUI actions (RUN) are sent once, one at a time, after the input is checked against the descriptors; no reply is "may have run", never retried, then `refreshConfigAsync`. Paused actions on a real-time loop are blocked while armed or arming; loop actions stay enabled. Forms are inline, never modal.
