# CLAUDE.md (protocol)

Rules for working in `protocol/`. The repo map and cross-cutting rules are in the root [CLAUDE.md](../CLAUDE.md). The firmware's conventions are in [firmware/CLAUDE.md](../firmware/CLAUDE.md).

## What this is

The wire library shared by the firmware and the host: framing, CRCs, the frame scanner and the field codec, plus the generated registry, diag code table and descriptor format. See [README.md](README.md).

## Rules

- **Pure C++20.** No ESP-IDF, FreeRTOS, `esp_log`, `sdkconfig.h` or OS headers, and no `CONFIG_*` symbols. Anything that needs them stays in the firmware (`uart_comm` supplies the driver, the clock and the logging).
- **Namespace `drivelink::protocol`**, headers under `include/drivelink/protocol/`. Types and enumerators PascalCase, functions camelCase, constants `k`-prefixed `constexpr`, members `m_`.
- **No allocation after construction, no blocking, no exceptions or RTTI.** The firmware calls this code from real-time-adjacent tasks. A constructor may allocate once (the `Scanner` window).
- **No logging, no clock.** Return results and counters, and let the caller log.
- **Untrusted input.** Every function that reads bytes from the wire checks lengths first and rejects instead of reading past the end. Frame payloads are views into the scanner's window, valid until its next call.
- **Generated headers.** Everything under `include/drivelink/protocol/gen/` is generated by `tools/gen/gen.py` from `protocol/defs/`. Never edit it. Change the YAML (or the generator) and regenerate, and commit both. The generated headers follow the same rules as the rest of `protocol/`: pure C++20, `constexpr` tables, no allocation. The hand-written descriptor format is `include/drivelink/protocol/defs.hpp`; a change to it is a change to the generator too.
- **Wire changes.** Any change to the frame layout or to a codec's encoding is a protocol change: update `docs/protocol/`, the firmware, the host code and the Python HIL reference (`firmware/test/uart_comm/protocol.py`) in the same PR, and bump the protocol versions.
- **Tests.** Every header has tests in `protocol/test/`: round trips, exact lengths, rejection of malformed input, and the resync cases for the scanner. A new `.cpp` joins `PROTOCOL_DIR` test sources in `firmware/test/native/CMakeLists.txt` until `protocol/` has its own test target. Changes to the generator come with tests in `tools/gen/tests/`.
- **Warnings are errors** in the native test build, and the IDF build must stay warning-free.

## Core wire contract

Core codecs are in core_codec.hpp; enums come from registry.yaml wire_enums.
Descriptor enum values in defs.hpp are wire values. Complete descriptor sizes
are generator-checked; firmware's payload cap must meet kDescriptorMinPayload.
Core v7 and diagnostic v3 are documented in docs/protocol/core.md and diag.md.
